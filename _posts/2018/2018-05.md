# Branch Recognition and WP-CLI installer issues

*Devlog: 2018-05*

In May I authored commits in [Raruto/wordpress-git](https://github.com/Raruto/wordpress-git).

![Illustration of wordpress-git](../img/wordpress-git-composer.jpg)

*An illustration of wordpress-git.*

Alongside that, I opened an [issue about inconsistent branch recognition](https://github.com/afragen/git-updater/issues/679) in Git Updater. Another snag appeared when calling its installer outside WP-CLI: the code tried to use a CLI-specific installer class that wasn't available in that context.

My [pull request](https://github.com/afragen/git-updater/pull/680) addressed that difference between execution contexts and was merged on May 13. The kind of bug that hides until the same operation takes a different route.

This installer fix followed earlier work on making [Git Updater](https://github.com/afragen/git-updater), then known as GitHub Updater, easier to diagnose. After reporting a [GitLab webhook timeout](https://github.com/afragen/git-updater/issues/663), I proposed [REST process logging](https://github.com/afragen/git-updater/pull/666) and [hook logging with interface changes](https://github.com/afragen/git-updater/pull/668). The latter was merged in April; its discussion weighed the value of local logs against duplicating information already available on the Git host.
