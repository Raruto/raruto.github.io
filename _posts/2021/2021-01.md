# Cockpit Pull Requests, Forms, and Add-on Commits

*Devlog: 2021-01*

## Building a Blog Around Cockpit

*Projects: 2021-01*

My [cockpit-blog](https://github.com/Raruto/cockpit-blog) repository dates back to January. It's a small blog implementation with a router, initially based on a [Cockpit tutorial](https://github.com/Raruto/cockpit-legacy-docs/blob/master/tutorials/simple_blog.md).

## Inside Cockpit: Routes, Forms, and Tests

*Contributions: 2021-01*

Looking back to January, my work with [Cockpit CMS](https://github.com/agentejo/cockpit) went beyond the add-ons I later published on Packagist. I proposed a [routing script](https://github.com/agentejo/cockpit/pull/1395) for PHP's built-in server after encountering a 404 on the install route.

Forms were another recurring theme. I suggested [reorganizing submission logic](https://github.com/agentejo/cockpit/pull/1399) to make it more extensible, and [moving the empty-data check](https://github.com/agentejo/cockpit/pull/1411) so the submission hook could also handle a form containing only uploaded files. I also proposed a [small PHPUnit starting point](https://github.com/agentejo/cockpit/pull/1406) for the forms module.

These were pull requests, not merged changes. They provide a look at the questions behind my [Extended Forms add-on]({{ '/blog/2021-01-29-cockpit-forms-packages.html' | relative_url }}) from the same month.

## Forms, Files, and a Little Honeypot

*Contributions: 2021-01*

Looking back to January 29, I published two Cockpit CMS add-ons on Packagist. [Extended Forms](https://packagist.org/packages/raruto/cockpit-extended-forms) adds handling for uploaded files and changes to the forms opening, closing and submission APIs. That work sits alongside the Cockpit forms contributions in my [January devlog]({{ '/blog/2021-01.html' | relative_url }}).

[Honeypot](https://packagist.org/packages/raruto/cockpit-honeypot) adds a setting and a honeypot field to forms, validates the submitted field and excludes invalid submissions from saved entries. It's one technique for dealing with unwanted submissions, not a promise to catch every bot.

Both package pages describe Composer installation and list compatibility with Cockpit 0.11.2. These are historical add-ons, so check the project's version and requirements before trying them on a newer installation.

## A Honeypot for Cockpit Forms

*Projects: 2021-01*

My [Honeypot](https://github.com/Raruto/cockpit-honeypot) repository and its [Packagist package](https://packagist.org/packages/raruto/cockpit-honeypot) date back to January 29. The add-on offers a honeypot option for Cockpit CMS forms.

The README describes adding and validating a field, then excluding invalid submissions from saved entries. It's one technique for reducing unwanted submissions, not a guarantee against spam. The add-on documents compatibility with Cockpit 0.11.2; check the version before using it with a newer installation.

## Let the Browser Load Images Lazily

*Contributions: 2021-01*

Looking back to January 29, I published [Native Lazy Loading](https://packagist.org/packages/raruto/cockpit-native-lazy-loading), a Cockpit CMS add-on that adds `loading="lazy"` to images in content from the TinyMCE and HTML editors.

The idea was to use the browser's native image-loading feature rather than require a separate JavaScript library. Browsers that don't support the attribute can simply ignore it. The package page lists compatibility with Cockpit 0.11.2, so it's worth checking the version before using this historical add-on today.
