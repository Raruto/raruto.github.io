# Dependency Installer Pull Requests and Leaflet Plugin Commits

*Devlog: 2020-02*

In February I continued working on [wp-dependency-installer](https://github.com/afragen/wp-dependency-installer), alongside several Leaflet plugins. I also reported issues and reviewed pull requests there, while two smaller WordPress integrations brought work outside the mapping projects.

I also authored commits across [leaflet-elevation](https://github.com/Raruto/leaflet-elevation), [leaflet-ui](https://github.com/Raruto/leaflet-ui), [leaflet-trails](https://github.com/Raruto/leaflet-trails) and [raruto.github.io](https://github.com/Raruto/raruto.github.io), plus several smaller plugins like leaflet-kmz and leaflet-pegman.

![Illustration of leaflet-elevation](../img/leaflet-elevation.png)

*A current illustration of leaflet-elevation.*

On [Send PDF for Contact Form 7](https://github.com/restezconnectes/send-pdf-for-contact-form-7), I reported an [`.htaccess` directive causing server errors](https://github.com/restezconnectes/send-pdf-for-contact-form-7/issues/5) on shared hosting and a [`$ is not a function` error](https://github.com/restezconnectes/send-pdf-for-contact-form-7/issues/6) when deleting a PDF in the admin. The reports document what I encountered, not whether the issues were fixed. A separate [pull request](https://github.com/restezconnectes/send-pdf-for-contact-form-7/pull/7) added a GitHub Plugin URI header for GitHub Updater and was merged on February 15.

I also forked [iubenda-for-wp](https://github.com/Raruto/iubenda-for-wp), a plugin originally maintained by [Ian James](https://github.com/injms/iubenda-for-wp), and proposed [shortcode support and coding-style changes](https://github.com/injms/iubenda-for-wp/pull/1). The pull request was not merged. Its README describes retrieving and caching policies through Iubenda's API; check the current service terms before relying on this historical integration.

The dependency installer work included a [required label](https://github.com/afragen/wp-dependency-installer/pull/39), passing [configuration to `run()`](https://github.com/afragen/wp-dependency-installer/pull/44), clearer [install conditions](https://github.com/afragen/wp-dependency-installer/pull/48), and a [chainable initialization API](https://github.com/afragen/wp-dependency-installer/pull/59). I also raised questions about [Basic Authentication headers](https://github.com/afragen/wp-dependency-installer/issues/41) and a [`get_config` abstraction](https://github.com/afragen/wp-dependency-installer/issues/57), and reviewed proposals for [customization filters](https://github.com/afragen/wp-dependency-installer/pull/55) and [admin notices](https://github.com/afragen/wp-dependency-installer/pull/60). Earlier suggestions for a clearer dependency label and required-plugin notice ([#35](https://github.com/afragen/wp-dependency-installer/pull/35), [#37](https://github.com/afragen/wp-dependency-installer/pull/37)) were proposals, not merged changes.
