## PDFs, Forms, and a Couple of WordPress Errors

*Contributions: 2020-02*

Looking back to February, I filed two reports on [Send PDF for Contact Form 7](https://github.com/restezconnectes/send-pdf-for-contact-form-7), a plugin for generating PDFs from form submissions.

One described an [`.htaccess` directive causing server errors](https://github.com/restezconnectes/send-pdf-for-contact-form-7/issues/5) on shared hosting. The other reported a [`$ is not a function` error](https://github.com/restezconnectes/send-pdf-for-contact-form-7/issues/6) when deleting a PDF from the admin page. The reports document what I encountered; they don't establish that either problem was fixed.

I also sent a [small pull request](https://github.com/restezconnectes/send-pdf-for-contact-form-7/pull/7) adding a GitHub Plugin URI header for use with GitHub Updater. It was merged on February 15, bringing two bits of my WordPress work together.

## A Shortcode for an Iubenda Policy

*Projects: 2020-02*

Looking back to February, I forked [iubenda-for-wp](https://github.com/Raruto/iubenda-for-wp), a WordPress plugin originally maintained by [Ian James](https://github.com/injms/iubenda-for-wp). Its README describes retrieving a policy through Iubenda's API and caching it for display on a site.

I proposed [shortcode support and WordPress coding-style changes](https://github.com/injms/iubenda-for-wp/pull/1) upstream. The pull request was not merged. The project's documentation also describes a paid-service requirement for the non-JavaScript API, so check Iubenda's current terms before relying on this historical integration.

## Untangling WordPress Plugin Dependencies

*Contributions: 2020-02*

Looking back to early 2020, I contributed to [WP Dependency Installer](https://github.com/afragen/wp-dependency-installer), a PHP class for installing WordPress plugin dependencies.

Some proposals were about making dependencies easier to understand in the admin interface. I suggested a more visible [dependency label](https://github.com/afragen/wp-dependency-installer/pull/35) and a [notice for required plugins](https://github.com/afragen/wp-dependency-installer/pull/37) that would help explain which plugin needed them. These were proposals, rather than merged changes.

Other pull requests made it into the project: passing [configuration to `run()`](https://github.com/afragen/wp-dependency-installer/pull/44), making the [install and activation notice code clearer](https://github.com/afragen/wp-dependency-installer/pull/48), and adding a [chainable initialization API](https://github.com/afragen/wp-dependency-installer/pull/59). That last one came with a confession in the pull request: I'm a JavaScript guy.
