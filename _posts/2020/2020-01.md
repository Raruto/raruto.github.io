# Contributions to Local Development and Dependency Installer

*Devlog: 2020-01*

In January I contributed to [afragen/local-development](https://github.com/afragen/local-development), opening issues about [detecting plugins under development](https://github.com/afragen/local-development/issues/4), [broken README images](https://github.com/afragen/local-development/issues/3), and the plugin's [version 2.5.0 listing](https://github.com/afragen/local-development/issues/11). I also sent pull requests for [localhost styling](https://github.com/afragen/local-development/pull/6), [custom plugin headers with icon links](https://github.com/afragen/local-development/pull/7), and [keeping the version-control icon in place](https://github.com/afragen/local-development/pull/8), and authored several commits there.

Later in the month I moved over to [afragen/wp-dependency-installer](https://github.com/afragen/wp-dependency-installer), where I asked [how to contribute to develop](https://github.com/afragen/wp-dependency-installer/issues/34) and opened pull requests to [increase the "Plugin dependency" label visibility](https://github.com/afragen/wp-dependency-installer/pull/35), add a [dismiss label](https://github.com/afragen/wp-dependency-installer/pull/36), and introduce a [mandatory notice](https://github.com/afragen/wp-dependency-installer/pull/37), along with a few commits.

Elsewhere, I filed ideas on [git-updater](https://github.com/afragen/git-updater), such as an [REST API access log](https://github.com/afragen/git-updater/issues/837) and [tips to force check for updates](https://github.com/afragen/git-updater/issues/840), plus a [remote REST API endpoints](https://github.com/afragen/git-remote-updater/issues/3) issue on git-remote-updater. I also opened a [Version 1.0.0 pull request](https://github.com/szepeviktor/github-link/pull/10) on github-link and authored commits in [Raruto/wp-devops](https://github.com/Raruto/wp-devops).

That month I also sent a few suggestions for the BuddyPress integration in Events Manager. One [patch](https://wordpress.org/support/topic/patch-custom-buddypress-navigation-slugs/) made navigation slugs easier to customize or translate; another [report](https://wordpress.org/support/topic/code-fix-buddypress-tab-title-invalid-string/) concerned an events-tab label that was difficult to translate. I suggested showing the [attending tab and profile information](https://wordpress.org/support/topic/code-fix-buddypress-attending-tab-conditional-loading/) only when bookings were enabled. The support team said it would pass the reports to the developers, and I shared references in a [discussion about event duration](https://wordpress.org/support/topic/event-duration/#post-12305927).

One of my [Local Development pull requests](https://github.com/afragen/local-development/pull/5) handled a less obvious case: a plugin could sit inside a parent directory already under version control. The change was merged on January 19 and appears in the 2.5.0 changelog. The plugin marks selected development plugins and themes in the WordPress admin and prevents their updates.
